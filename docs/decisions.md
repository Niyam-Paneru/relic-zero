# Decisions

## One active invitation

There is one chain, not a pile of invite links. That is the whole social constraint.

## Store hashes, not invitation plaintext

The server needs to verify a capability; it does not need to keep the secret value around for sightseeing.

## Replay derives the visible state

Bless/corrupt totals are derived from history rather than maintained as a second source of truth.

## Manual forwarding stays manual

The product is about custody. Automatically messaging the next person would turn a handoff ritual into a notification system.
